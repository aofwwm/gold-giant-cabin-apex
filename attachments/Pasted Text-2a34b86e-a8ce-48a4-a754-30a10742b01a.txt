The public Dating invitation now loads correctly.

The remaining bug is recipient response submission.

Current behaviour:

Recipient presses:

“I’m up for it”

and Kairos shows:

“That reply did not land.”

This is almost certainly because the anonymous recipient is trying to directly UPDATE:

public.dating_invitations

and RLS blocks it.

DO NOT disable RLS.

DO NOT add broad anonymous UPDATE permission.

I have created / will create this controlled RPC:

public.respond_to_dating_invitation(
  p_invite_slug text,
  p_response text,
  p_note text
)

Replace any direct:

supabase
  .from("dating_invitations")
  .update(...)

from the public invitation page.

Instead call:

const { data, error } = await supabase.rpc(
  "respond_to_dating_invitation",
  {
    p_invite_slug: inviteSlug,
    p_response: "sounds_good",
    p_note: note || null
  }
);

For:

“I’m up for it”

send:

p_response = "sounds_good"

For:

“Suggest another time”

send:

p_response = "alternate_time_requested"

IMPORTANT:

Do not allow arbitrary status values.

The recipient must not be able to edit:

- itinerary
- private plan
- recipient name
- planner notes
- invite slug
- public payload
- visibility

Only response/status + recipient note should be writable through this RPC.
